# 📖 راهنمای کامل ServerTools — از صفر تا صد

راهنمای قدم‌به‌قدم استفاده؛ از نصب تا بهینه‌سازی کامل، امنیت، ابزارها و بازگردانی.
نکته: جمله‌های فارسی این راهنما طوری نوشته شده‌اند که در گیت‌هاب به‌هم نریزند؛ دستورات ترمینال هم همیشه داخل بلوک کد و چپ‌چین هستند.

---

## 🧰 ۱) این ابزار چیست و برای چه کسی است؟

ابزار ServerTools یک بهینه‌ساز حرفه‌ای سرور لینوکس است که مخصوص **سرورهای VPN** ساخته شده:
نودهای Xray/Reality (مثل `marzban-node` و `pg-node`)، پنل‌های Marzban/Pasarguard، وایرگارد، x-ui، Hiddify و… — و البته برای **بهینه‌سازی عمومی هر سرور لینوکسی** هم کامل است.

ویژگی کلیدی: ابزار «یک‌بار اجرا» است؛ تنظیمات را در کرنل می‌نویسد و خارج می‌شود.
هیچ سرویس و cron و telemetry‌ای نصب نمی‌کند — چه ۱۰۰ کاربر متصل باشد چه ۱۰۰هزار، مصرف خودِ ابزار صفر است. ⚡

## ✅ ۲) پیش‌نیازها

- دسترسی **root** لازم است (یا `sudo -i`) 🔑
- سیستم‌عامل Ubuntu 20.04 به بالا یا Debian 11 به بالا (تست‌شده در CI؛ توزیع‌های دیگر معمولاً کار می‌کنند) 🐧
- اتصال اینترنت برای دانلود اسکریپت 🌐

## 📥 ۳) نصب و اجرا

اجرای مستقیم اسکریپت:

```bash
bash <(curl -fsSL4 https://raw.githubusercontent.com/Sir-Adnan/server-tools/main/dist/server-tools.sh)
```

نصب به‌عنوان دستور کوتاه `st` (پیشنهادی):

```bash
bash <(curl -fsSL4 https://raw.githubusercontent.com/Sir-Adnan/server-tools/main/dist/server-tools.sh) --install
```

از این به بعد کافی است تایپ کنید `st` — و برای آپدیت: `st --update` 🔄

> نکته 💡: اگر سرور curl نداشت، به جای `curl -fsSL4` از `wget -qO-` استفاده کنید:
> `bash <(wget -qO- URL)`

## 🖥️ ۴) آشنایی با داشبورد

با اجرای `st` منوی اصلی بالا می‌آید. بالای منو یک داشبورد فوری می‌بینید:

- مشخصات سرور (OS / Kernel / RAM)
- آی‌پی عمومی سرور (یک بار گرفته و کش می‌شود)
- وضعیت TCP: الگوریتم congestion فعلی (مقدار `bbr` یعنی فعال ✅) و qdisc
- سطر Detected: چیزی که روی سرور تشخیص داده شده (مثلاً `pg-node` یا `wireguard`)

## ⚡ ۵) بهینه‌سازی سریع (Quick Optimize) — گزینه ۱

ساده‌ترین مسیر؛ برای ۹۰٪ کاربران همین کافی است:

1. گزینه **[1] Quick Optimize** را بزنید.
2. پلن نمایش داده می‌شود: پروفایل تشخیص‌داده‌شده، تیر ظرفیت (S/M/L/XL بر اساس RAM)، سایز جدول conntrack و **تخمین مصرف RAM کرنل** — همه‌چیز قبل از اعمال، شفاف.
3. سرویس DNS را انتخاب کنید (حرف `t` سرعت همه را تست می‌کند؛ عدد `0` یعنی **به DNS فعلی دست نزن**).
4. تأیید کنید — مراحل یکی‌یکی اجرا می‌شوند:

```text
[1/5] Kernel network tuning (sysctl, tier M) ... OK
[2/5] File-descriptor limits (nofile) ... OK
[3/5] Journald cap & NTP ... OK
[4/5] Swap file ... SKIPPED
[5/5] DNS (1.1.1.1 / 1.0.0.1) ... OK
```

معنی وضعیت‌ها: انجام شد ✅ (OK) · لازم نبود ⏭️ (SKIPPED — مثلاً swap از قبل فعال بود) · انجام شد با نکته ⚠️ (WARN — جزئیات در لاگ) · انجام نشد ❌ (FAILED) — این ابزار هیچ‌وقت برای کارِ خراب «OK» نمی‌گوید.

در پایان اگر limits تغییر کرده باشد، پیشنهاد **ری‌استارت کانتینر/سرویس نود** را می‌دهد تا سقف فایل جدید را بگیرد — تأیید با شماست.

## 🎛️ ۶) بهینه‌سازی سفارشی (Custom Optimize) — گزینه ۲

برای کنترل کامل روی همه‌چیز:

- انتخاب **پروفایل**: عمومی (`general`) · نود Xray (`vpn-node`) · وایرگارد (`wireguard`) · سرور پنل (`panel`) · همه‌چیز (`full`)
- انتخاب **تیر ظرفیت**: پیش‌فرض از روی RAM؛ با S/M/L/XL قابل تغییر
- تعیین **تعداد کاربر مورد انتظار** 🔥: اگر عدد بدهید (مثلاً `10000`)، جدول conntrack از روی **تعداد واقعی کاربر** سایز می‌شود نه RAM — و اگر ترکیب با RAM سرور جور درنیاید، **هشدار عددی صادقانه** می‌گیرید (تخمین نیاز در برابر RAM موجود).
- سپس تک‌تک ماژول‌ها (limits، journald/NTP، swap، DNS) را تیک می‌زنید.

> قاعده سرانگشتی 📏: هر **۱۰هزار کاربر همزمان ≈ ۸ گیگابایت RAM**. اگر کاربر زیاد و RAM کم دارید، بهترین راه تقسیم کاربران بین دو نود است، نه فشار به یک سرور کوچک.

## 🤖 ۷) حالت غیرتعاملی — مدیریت چند نود

برای اجرا روی چندین سرور بدون هیچ سوالی (مثلاً از داخل اسکریپت یا Ansible):

```bash
st --auto --profile vpn-node --tier L --dns cloudflare
st --auto --users 10000 --dns shecan --no-swap
```

نکته‌ها: بدون `--dns` به DNS دست نمی‌زند؛ گزینه‌های `--no-swap` و `--no-limits` و `--no-extras` مراحل را حذف می‌کنند.

## 🔍 ۸) پیش‌نمایش بدون اعمال (Dry Run)

می‌خواهید قبل از اعمال ببینید دقیقاً چه چیزی تغییر می‌کند؟

```bash
st --dry-run
st --dry-run --profile vpn-node --users 10000
```

خروجی شامل فایل sysctl کامل + مقایسه تک‌تک کلیدها با مقدار فعلی کرنل است (`فعلی -> جدید`) — و در انتها: «X کلید تغییر می‌کرد؛ **هیچ‌چیزی اعمال نشد**». 🛡️

## 🩺 ۹) بررسی سلامت (Doctor)

بعد از ریبوت، آپدیت کرنل یا نصب پنل جدید، ممکن است بعضی تنظیمات از بین بروند. با این دستور در چند ثانیه معلوم می‌شود:

```bash
st --verify        # یا گزینه [4] در منو
st --verify --json # برای اسکریپت و مانیتورینگ
```

خروجی برای هر بخش یکی از سه حالت است: در حال اجرا ✅ (OK) · تنظیم‌نشده ⏭️ · از تنظیم خارج‌شده ⚠️ (DRIFT همراه با راه‌حل). ضمناً اثر واقعی تنظیمات (میزان retransmit و drop از زمان آخرین بهینه‌سازی) هم نمایش داده می‌شود.

## 📊 ۱۰) وضعیت و گزارش

- گزارش وضعیت: `st --status` یا گزینه [3] — سیستم، CPU/RAM/دیسک، شبکه و تنظیمات TCP
- گزارش پشتیبانی: `st --report` یا Tools → Support report — **گزارش متنی کامل** برای تیکت؛ چاپ می‌شود و در مسیر `/var/lib/server-tools/` هم ذخیره می‌شود 📄

## 🔐 ۱۱) امنیت — گزینه ۶ (همه اختیاری، با تأیید شما)

- فایروال **UFW** 🧱: پورت SSH خودکار تشخیص و **قبل از هر قانون deny** باز می‌شود (ضد قفل‌شدن)؛ بعد پورت‌های دلخواه (مثل `443/tcp`) را می‌دهید و فعال می‌کنید. اگر Docker فعال باشد، هشدار می‌گیرید که پورت‌های publish شده از UFW عبور می‌کنند.
- محافظ **fail2ban** 🛡️: جلوگیری از brute-force روی SSH — تنها سرویس دائمی کل پروژه (~۲۰ مگابایت RAM) و فقط با رضایت صریح شما نصب می‌شود.
- سخت‌سازی **SSH** 🔑: خاموش‌کردن ورود با پسورد **فقط وقتی کلید SSH دارید** — و config قبل از ری‌استارت با `sshd -t` اعتبارسنجی می‌شود تا پشت در نمانید.
- پروفایل **ضدabuse** 🚫: بستن SMTP و پورت‌های کرم‌خیز خروجی و رنج‌های خصوصی دیتاسنتر — جلوگیری از گزارش abuse (شبکه‌ی خود سرور باز می‌ماند).
- محدودسازی **پورت API نود** 🎯: پورت‌های 62050/62051 فقط از IP پنل قابل دسترس شوند.

## 🧪 ۱۲) ابزارهای شبکه — گزینه ۷

- ماتریس پینگ 📡: تأخیر و packet loss به مقاصد ایران (زیرساخت، شکن) و جهانی — برای سنجش کیفیت لوکیشن سرور برای کاربران ایران عالی است.
- تست سرعت DNS ⏱️: زمان واقعی پاسخ هر سرویس (با کوئری واقعی dig).
- کلمپ MSS 🩹: درمان مشکل کلاسیک «وایرگارد وصل می‌شود ولی سایت باز نمی‌شود».
- بازرسی Docker+UFW 🐳: نمایش پورت‌هایی که از فایروال عبور می‌کنند.
- کرنل XanMod با BBRv3 🚀: پیشرفته — کرنل را عوض می‌کند! فقط اگر می‌دانید چه می‌کنید و به کنسول ریکاوری provider دسترسی دارید.
- تست پهنای باند و بنچمارک ⚡: speedtest یا دانلود HTTP بدون نیاز به نصب چیزی + سنجش سریع CPU و دیسک.
- نمای زنده 📺: نمایش لحظه‌ای conntrack، سوکت‌ها و ترافیک زیر بار (با q خارج می‌شوید).
- تعویض mirror اپت 🇮🇷: برای سرورهای داخل ایران، `apt` را چند برابر سریع‌تر می‌کند (و در صورت خطا خودکار برمی‌گردد).

## 🐳 ۱۳) نود و داکر — گزینه ۸

- پشتیبان‌گیری از کانفیگ نود 💾: از `/opt/marzban-node`، `/opt/pg-node`، `/etc/wireguard` و… یک آرشیو رمزنشده ولی محافظت‌شده می‌سازد (شامل گواهی‌ها — محرمانه نگه دارید).
- نصب نود 📦: دستور رسمی هر پروژه **قبل از اجرا کامل نمایش داده می‌شود** و فقط با تأیید شما اجرا می‌شود؛ ServerTools نصب‌کننده‌ی خودش را جایگزین نمی‌کند.
- محدودیت فایل کانتینرها 🔧: کانتینرها سقف فایل را از داکر می‌گیرند نه از `limits.d` — این گزینه `default-ulimits` را تنظیم می‌کند.

## ♻️ ۱۴) بازگردانی (Rollback)

هر تغییری که ابزار می‌دهد، قبل از اعمال در manifest ثبت و بکاپ می‌شود؛ نسخه دست‌نخورده‌ی هر فایل هم برای همیشه نگه داشته می‌شود.

```bash
st --rollback            # یا گزینه [5] در منو
st --rollback-original   # بازگشت کامل به وضعیت قبل از اولین اجرا
```

آخرین اجرا برعکس می‌شود: فایل‌های تغییریافته برمی‌گردند، فایل‌های ساخته‌شده حذف می‌شوند، سرویس‌های ایجادشده غیرفعال می‌شوند و sysctl دوباره بارگذاری می‌شود.

## 🆘 ۱۵) عیب‌یابی سریع

| مشکل | راه‌حل |
| --- | --- |
| خطای «must be run as root» 🔒 | با `sudo -i` وارد شوید و دوباره اجرا کنید |
| دانلود انجام نمی‌شود 🌐 | از نسخه `wget -qO-` استفاده کنید یا `-4` را بردارید |
| فعال نشدن BBR 📉 | کرنل باید ۴.۹ به بالا باشد؛ با `uname -r` چک کنید |
| بررسی اینکه DNS واقعاً عوض شده 📡 | خط «Servers in effect» در `st --status` را ببینید (یا `resolvectl status`) — همان چیزی است که واقعاً پاسخ می‌دهد |
| مسیر لاگ 🗒️ | فایل `/var/log/server-tools.log` |
| به‌هم‌ریختگی رنگ خروجی 🎨 | اجرای `st --no-color` یا متغیر `NO_COLOR=1` |
