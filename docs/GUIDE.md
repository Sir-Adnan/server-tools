# 📖 راهنمای کامل ServerTools — از صفر تا صد

راهنمای قدم‌به‌قدم استفاده از ServerTools؛ از نصب تا بهینه‌سازی کامل، امنیت، ابزارها و بازگردانی.
متن فارسی راست‌چین است و دستورات ترمینال برای جلوگیری از به‌هم‌ریختگی، چپ‌چین نمایش داده می‌شوند.

</div>

---

<div dir="rtl" align="right">

## 🧰 ۱) این ابزار چیست و برای چه کسی است؟

ServerTools یک بهینه‌ساز حرفه‌ای سرور لینوکس است که مخصوص **سرورهای VPN** ساخته شده:
نودهای Xray/Reality (مثل `marzban-node` و `pg-node`)، پنل‌های Marzban/Pasarguard، WireGuard، x-ui، Hiddify و… — و البته برای **بهینه‌سازی عمومی هر سرور لینوکسی** هم کامل است.

ویژگی کلیدی: ابزار **one-shot** است؛ تنظیمات را در کرنل می‌نویسد و خارج می‌شود.
هیچ سرویس و cron و telemetry‌ای نصب نمی‌کند — چه ۱۰۰ کاربر متصل باشد چه ۱۰۰هزار، مصرف خودِ ابزار صفر است. ⚡

## ✅ ۲) پیش‌نیازها

- 🔑 دسترسی **root** (یا `sudo -i`)
- 🐧 Ubuntu 20.04 به بالا یا Debian 11 به بالا (تست‌شده در CI؛ توزیع‌های دیگر معمولاً کار می‌کنند)
- 🌐 اتصال اینترنت برای دانلود اسکریپت

## 📥 ۳) نصب و اجرا

### روش پیشنهادی — اجرا و نصب دستور `st`

اول اسکریپت را اجرا کنید:

</div>

```bash
bash <(curl -fsSL4 https://raw.githubusercontent.com/Sir-Adnan/server-tools/main/dist/server-tools.sh)
```

<div dir="rtl" align="right">

سپس برای اینکه دفعات بعد فقط با دستور کوتاه `st` اجرا شود:

</div>

```bash
bash <(curl -fsSL4 https://raw.githubusercontent.com/Sir-Adnan/server-tools/main/dist/server-tools.sh) --install
```

<div dir="rtl" align="right">

از این به بعد کافی است تایپ کنید: `st` — و برای آپدیت: `st --update` 🔄

> 💡 اگر سرور curl نداشت، به جای `curl -fsSL4` از `wget -qO-` استفاده کنید:
> `bash <(wget -qO- URL)`

## 🖥️ ۴) آشنایی با داشبورد

با اجرای `st` منوی اصلی بالا می‌آید. بالای منو یک داشبورد فوری می‌بینید:

- **OS / Kernel / RAM** — مشخصات سرور
- **Public IPv4** — آی‌پی عمومی (یک بار گرفته و کش می‌شود)
- **TCP** — الگوریتم congestion فعلی (`bbr` یعنی فعال ✅) و qdisc
- **Detected** — چیزی که روی سرور تشخیص داده شده (مثلاً `pg-node` یا `wireguard`)

## ⚡ ۵) بهینه‌سازی سریع (Quick Optimize) — گزینه ۱

ساده‌ترین مسیر؛ برای ۹۰٪ کاربران همین کافی است:

1. گزینه **[1] Quick Optimize** را بزنید.
2. پلن نمایش داده می‌شود: پروفایل تشخیص‌داده‌شده، تیر ظرفیت (S/M/L/XL بر اساس RAM)، سایز جدول conntrack و **تخمین مصرف RAM کرنل** — همه‌چیز قبل از اعمال، شفاف.
3. DNS را انتخاب کنید (یا `t` برای تست سرعت همه، یا `0` که یعنی **دست نزن به DNS فعلی**).
4. تأیید کنید — مراحل یکی‌یکی اجرا می‌شوند:

</div>

```text
[1/5] Kernel network tuning (sysctl, tier M) ... OK
[2/5] File-descriptor limits (nofile) ... OK
[3/5] Journald cap & NTP ... OK
[4/5] Swap file ... SKIPPED
[5/5] DNS (1.1.1.1 / 1.0.0.1) ... OK
```

<div dir="rtl" align="right">

معنی وضعیت‌ها: ✅ **OK** انجام شد · ⏭️ **SKIPPED** لازم نبود (مثلاً swap از قبل فعال بود) · ⚠️ **WARN** انجام شد ولی با نکته (در لاگ) · ❌ **FAILED** انجام نشد — این ابزار هیچ‌وقت برای کارِ خراب «OK» نمی‌گوید.

در پایان اگر limits تغییر کرده باشد، پیشنهاد **restart کانتینر/سرویس نود** را می‌دهد تا سقف فایل جدید را بگیرد — تأیید با شماست.

## 🎛️ ۶) بهینه‌سازی سفارشی (Custom Optimize) — گزینه ۲

برای کنترل کامل:

- **پروفایل**: `general` (سرور عمومی) · `vpn-node` (نود Xray) · `wireguard` · `panel` (سرور پنل) · `full` (همه‌چیز)
- **تیر ظرفیت**: پیش‌فرض از روی RAM؛ با S/M/L/XL قابل override
- **تعداد کاربر مورد انتظار** 🔥: اگر عدد بدهید (مثلاً `10000`)، جدول conntrack از روی **تعداد واقعی کاربر** سایز می‌شود نه RAM — و اگر ترکیب با RAM سرور جور درنیاید، **هشدار عددی صادقانه** می‌گیرید (تخمین نیاز در برابر RAM موجود).
- سپس تک‌تک ماژول‌ها (limits، journald/NTP، swap، DNS) را تیک می‌زنید.

> 📏 قاعده سرانگشتی: هر **۱۰هزار کاربر همزمان ≈ ۸ گیگابایت RAM**. اگر کاربر زیاد و RAM کم دارید، بهترین راه تقسیم کاربران بین دو نود است، نه فشار به یک سرور کوچک.

## 🤖 ۷) حالت غیرتعاملی — مدیریت چند نود

برای اجرا روی چندین سرور بدون هیچ سوالی (مثلاً از داخل اسکریپت یا Ansible):

</div>

```bash
st --auto --profile vpn-node --tier L --dns cloudflare
st --auto --users 10000 --dns shecan --no-swap
```

<div dir="rtl" align="right">

نکته‌ها: بدون `--dns` به DNS دست نمی‌زند؛ `--no-swap` و `--no-limits` و `--no-extras` مراحل را حذف می‌کنند.

## 🔍 ۸) پیش‌نمایش بدون اعمال (Dry Run)

می‌خواهید قبل از اعمال ببینید دقیقاً چه چیزی تغییر می‌کند؟

</div>

```bash
st --dry-run
st --dry-run --profile vpn-node --users 10000
```

<div dir="rtl" align="right">

خروجی: فایل sysctl کامل + مقایسه تک‌تک کلیدها با مقدار فعلی کرنل (`فعلی -> جدید`) — و در انتها: «X کلید تغییر می‌کرد؛ **هیچ‌چیزی اعمال نشد**». 🛡️

## 📊 ۹) وضعیت و گزارش

- `st --status` یا گزینه [3]: گزارش کامل سیستم (CPU/RAM/دیسک/شبکه/تنظیمات TCP)
- `st --report` یا Tools → Support report: **گزارش متنی کامل** برای تیکت و پشتیبانی — چاپ می‌شود و در `/var/lib/server-tools/` هم ذخیره می‌شود 📄

## 🔐 ۱۰) امنیت — گزینه ۵ (همه اختیاری، با تأیید شما)

- 🧱 **UFW**: پورت SSH خودکار تشخیص و **قبل از هر قانون deny** باز می‌شود (ضد قفل‌شدن)؛ پورت‌های دلخواه (مثل `443/tcp`) را می‌دهید و فعال می‌کنید. اگر Docker فعال باشد، هشدار می‌گیرید که پورت‌های publish شده از UFW عبور می‌کنند.
- 🛡️ **fail2ban**: محافظ brute-force برای SSH — تنها سرویس دائمی کل پروژه (~۲۰MB RAM) و فقط با رضایت صریح شما نصب می‌شود.
- 🔑 **SSH hardening**: خاموش‌کردن ورود با پسورد **فقط وقتی کلید SSH دارید** — و config قبل از restart با `sshd -t` اعتبارسنجی می‌شود تا پشت در نمانید.

## 🧪 ۱۱) ابزارهای شبکه — گزینه ۶

- 📡 **Ping matrix**: تأخیر و packet loss به مقاصد ایران (زیرساخت، شکن) و جهانی — برای سنجش کیفیت لوکیشن سرور برای کاربران ایران عالی است.
- ⏱️ **DNS latency**: سرعت واقعی پاسخ هر DNS (با کوئری واقعی dig).
- 🩹 **MSS clamping**: درمان مشکل کلاسیک «وایرگارد وصل می‌شود ولی سایت باز نمی‌شود».
- 🐳 **Docker+UFW audit**: نمایش پورت‌هایی که از فایروال عبور می‌کنند.
- 🚀 **XanMod kernel (BBRv3)**: پیشرفته — کرنل را عوض می‌کند! فقط اگر می‌دانید چه می‌کنید و به کنسول ریکاوری provider دسترسی دارید.

## ♻️ ۱۲) بازگردانی (Rollback)

هر تغییری که ابزار می‌دهد، قبل از اعمال در manifest ثبت و بکاپ می‌شود؛ نسخه دست‌نخورده‌ی هر فایل هم برای همیشه نگه داشته می‌شود.

</div>

```bash
st --rollback     # یا گزینه [4] در منو
```

<div dir="rtl" align="right">

آخرین اجرا برعکس می‌شود: فایل‌های تغییریافته برمی‌گردند، فایل‌های ساخته‌شده حذف می‌شوند، سرویس‌های ایجادشده غیرفعال می‌شوند و sysctl دوباره بارگذاری می‌شود.
